Portable assembly IR

Write one low-level language. Lower it into many assembly worlds.

CommonASM is a common intermediate assembly for language builders who do not want to write a separate backend by hand for every CPU, VM, toy machine, or esoteric target.

Target strategy

What a target claims is what CI checks.

A backend is only worth as much as the evidence behind it, so the three levels below are levels of evidence, not of ambition. Run --target-info TARGET to see which one a target is in.

Executed

One program that uses arithmetic, control flow, memory, the stack and syscalls is built for each of these, linked, run under qemu-user, and required to print the same thing as all the others. An answer that is merely well-formed does not pass.

  • x86_64-nasm, i386-nasm
  • aarch64-gnu, armv7a-gnu
  • riscv64-gnu, mips32-gnu, ppcg4-gnu
  • sparcv8-gnu, m68k, zarch

Assembled

Real assembly for a real assembler, which accepts every example on every commit. These share the emitters above, so what separates them is that nothing here can emulate them yet.

  • wasm through wat2wasm, thumb2-gnu, thumb-gnu
  • armv4-gnu, armv5-gnu, rv64i-gnu, riscv64-zbb
  • mips64-gnu, power1-gnu through power10-gnu
  • sparcv9-gnu, and the rest of the SPARC and PowerPC families

Pseudo assembly

Machines with very different memory models, tiny register sets, or esoteric semantics get readable pseudo assembly or a source encoding. These are for reading and for porting from, not for running.

  • chip8, subleq, redcode
  • brainfuck, fractran, cellular-automaton
  • pdp11, vax, mix, lc3

Language shape

A small assembly vocabulary for compiler backends.

CommonASM has sections, constants, data declarations, virtual registers, typed memory access, arithmetic, branches, function helpers, stack operations, and Linux-style syscall helpers for targets that can lower them.

examples/hello.cas
const stdout = 1

.data
msg: string "Hello from CommonASM\n"

.text
global _start

_start:
  syscall write, stdout, msg, msg_len
  syscall exit, 0

Using what a machine actually has

A portable language that still reaches the fast instruction.

A common subset that only ever emits what every machine can do is a middle-level language wearing assembly's clothes. These three let a program use the instruction its CPU really has, and still build for one that has never heard of it.

Extended operations

popcnt, clz, ctz, bswap, rol, ror, min, max, abs and sel are one instruction where the machine has one. Where it does not, each expands into ordinary CommonASM that goes through the same lowering as hand-written code, so the program still builds and still gives the same answer. 

popcnt r0  ; cpop on riscv64-zbb
           ; a SWAR fold on riscv64-gnu

min r0, r1 ; min  on riscv64-zbb
           ; csel on aarch64-gnu
           ; cmov on x86_64-nasm

--target-info TARGET lists which are native there; --emulate-extended expands them anyway, which is how the two paths are tested against each other.

Inline assembly

An asm block is not compiled. It goes into the output as written, so a program can reach anything its machine has. Consecutive blocks are alternatives for one spot: the first selector that matches wins, and a portable arm keeps the fast path optional. {r0} becomes whatever register the backend put r0 in. 

asm x86_64 {
  lea {r0}, [{r0} + {r0} * 2]
}
asm portable {
  mov r1, 3
  mul r0, r1
}

A spot where nothing matches is an error rather than a silently missing instruction.

Assembly to assembly

The lowering runs backwards too. --from FAMILY reads a whole assembly file back into CommonASM, which can then be compiled for a different machine, and --translate-asm does the same for an asm block whose selector did not match, instead of failing for want of an arm. 

commonasmc old.s --from aarch64 \
  --target x86_64-nasm -o new.asm

Every family's assembly is required to read back into the CommonASM it was generated from, on every commit.

Build and compile

The C AOT compiler is the reference implementation.

1

Build

gcc csrc/commonasmc.c -o build/commonasmc.exe
2

Inspect the CLI

build/commonasmc.exe --help
build/commonasmc.exe --version
build/commonasmc.exe --list-targets
build/commonasmc.exe --target-info wasm
3

Compile to a primary target

build/commonasmc.exe examples/hello.cas \
  --target x86_64-nasm \
  -o build/hello_x86.asm

build/commonasmc.exe examples/optimize.cas \
  --target x86_64-nasm \
  -O1 \
  -o build/optimize_x86.asm
4

Use a pipeline

Get-Content examples/vm_ir.cas | build/commonasmc.exe - \
  --target wasm \
  -o -
